口径与范围（issue #4 P1）

1. 会话流：两种消息都画成居中标记行

形状照上游 mobile/src/ui/transcript.tsx:879 AgentRow：居中、标记行 + 预览行两行、最大宽 320、预览一行省略。说法与上游同一套中文：已发消息给 / 来自（上游 Messaged / Message from，mobile/src/i18n/zh.ts:333-336）。

消息标记行第二行可点开
tool 带 agent（启动行）已发消息给 {智能体名} · {标题} [状态]提示词第一行是 → 详情
tool 带 target_agent_id（发消息行）已发消息给 {智能体名} · {标题} [状态]发给它的那句话是 → 详情
agent_message（它说的话）来自 {智能体名} · {标题}正文第一行是 → 详情
agent_message + failed来自 {智能体名} · {标题}正文第一行，红色是 → 详情

两处与上游不同，是有意的，需要你点头：

  • 标记行带状态词（上游不带）。理由：上游靠 logo 认智能体、靠点开认状态；avatar 本期不引 logo 资产，状态词是「不开浮层也知道干到哪」的唯一出口。状态词六档照上游 agentStatusWord 的中文：工作中 / 需要处理 / 待审核 / 已完成 / 运行失败 / 已停止。**适用范围（研发核出，已收窄）**：
    • 启动行：六档齐全（它自己带 AgentRun）。
    • 发消息行：状态要同会话反查启动行（上游 App 同口径）；启动行不在已加载窗口时**没有状态词**，这时标记行不为此留空位。
    • 报告行：上游只给 failed 一个布尔，所以**只在失败时画一个「运行失败」词**，成功不加（这条行存在本身就是完成信号，每行都挂「已完成」只是噪声）；同时预览行走红色。
  • 智能体名写进标记行（上游只有 logo）。理由同上：没有 logo，名字就是身份。名字用产品名不翻译（Claude Code / Codex / OpenCode / pi / fx，上游 model.rs:551 同口径）。

不再折进工具折叠块：带 agent / target_agent_id 的行从折叠块里摘出来；块里剩下的仍是普通工具（bash 等），头部不会再有 coding_agent 这个英文原名。

2. 详情浮层：从底部起的全高浮层

位置内容
把手 + 标题栏智能体标记 + 标题（最多 3 行）+ 关闭（iOS「完成」/ Android「关闭」）
状态行{智能体名} · {状态词} · {分支} · {设备}（缺的项不占位，失败时整行走失败色）
失败原因行仅 state === "failed" 且 outcome 非空时出现：失败原因：{outcome}，走失败色、可换行；其余情况不占位
动作行运行中一个「停止」；有 PR 时一个 PR 入口（#12）；都没有时整行不占位
主体（可滚）按时间顺序列步骤：提示词卡（超 6 行折叠，「显示更多」）/ 状态行 / 思考了 N 秒（可展开正文）/ 它说的话 / 工具步骤（读与搜索折成「浏览了 N 个文件 M 次搜索」，命令可展开输出，编辑带 +N −N）/ 计划清单 / 错误行
底部分支 + 改动统计（+184 −37，涉及 6 个文件）+ 关闭

只读：不放输入框（要跟智能体说什么，走 bot 转达，照上游）。

跟随：打开期间按 coding.transcript { chat_id, message_id } 拉，本机每 2 秒、跨设备每 5 秒；state 到 failed / stopped 就停；关掉浮层立即停，不留后台定时器。

关掉：点外面、按返回键（走已有的 useBackLayer，不穿透到会话列表）、底部按钮。

6. 一处取舍要说清：标记行里的标题会被截短

标记行的固定部分（「已发消息给」+ 标记 + 智能体名 + 分隔点 + 状态词）在 320px 里占约 210px，标题只剩约 110px，390pt 屏上可见 8–9 个字。上游没有状态词，标题能多拿约 4 个字。

我的取舍是保留状态词，理由：标题只用于「认得出是哪个任务」（前几个字通常够），而「干到哪了」是这一行唯一的可扫视信号，也是点开浮层的动机。完整标题在浮层标题栏里完整可读（最多 3 行）。

如果你更在意标题完整度，备选是把状态词移到预览行右端（标题能多 4 个字）—— 但状态会离标题变远，扫视时容易读成预览的一部分。你定。

7. 失败态（本次补充，2026-10-18）

复核时发现的缺口：启动失败的智能体从没进上游的 agent 表（by_row 查不到），所以点开浮层拉 coding.transcript 只会失败 —— 主体一片空白 + 一句英文报错。而上游给的真原因就在卡上的 outcome（桥接层已经收进协议了，界面一处没画）。

位置口径
桥接层上游的 That coding agent never started 要翻成 404（不是 502），且说清是「这个智能体没有跑起来」，不能说成「这一行不是启动行」——两种 404 是不同的错
浮层主体拉不到运行记录时**不弹错误框**，走已有空态「这次运行没有留下步骤。」（原因由下面那行给）
失败原因行状态行下方一行「失败原因：{outcome}」，仅 state === "failed" 且 outcome 非空；数据取会话流那一行的卡（fallback），不等 transcript

两处与上游不同，都是有意：

  • 不替换状态行（上游 macOS AgentCellView.swift:36 是整条替成「失败：{outcome}」）。理由：360pt 上 outcome 可能是一整句英文，替掉状态行就把「哪个智能体、哪个分支」挤掉了；上游那样写是因为它的 detail 只有一行位置，浮层里有两行。
  • stopped 的 outcome 本期不画（上游也只画 failed 那档）。stopped 的 outcome 常常就是「Stopped」这类词，摆在「失败原因：」后面是假话。状态词「已停止」已经说清了。要画得另起一档标签，P2 再说。
