删除会话「产品经理」？

这个会话和它的全部内容都会从所有设备上删掉：

  • 全部消息与附件
  • 已读标记
  • 正在运行的任务会被取消

不可撤销，也无法从回收站恢复。

滑动：数值尺子验收依据

项值
方向 · 进入横向|dx| ≥ 10px 且 |dx| ≥ 1.5·|dy|（向左为负，只有负向开格）
方向 · 交回纵向|dy| ≥ 10px 且 |dy| > |dx|
未起判区（1.0 < |dx|/|dy| < 1.5）既不横向也不纵向：行不跟手，方向等下一次移动；不按斜滑猜
起判前（|dx| < 10px）行不跟手（位移 0）
起手排除区v4 取消：左滑与系统返回手势（左缘向右拖）不再冲突，不再需要排除区
吸附 · 只有两态关（0）或全开（252）；没有中间停档（Adam 2026-10-18 定）
开档阈值该行上限的一半：三格行 open ≥ 126px → 全开 252；< 126 → 回 0
已开态向右滑≥ 42px → 关回 0；不足 42px → 回全开
拖动途中行 1:1 跟手（0–252），松手才吸附；不回弹到中间值
Hidden 行（两格）上限 168px；开档阈值 open ≥ 84px
动作槽每个 84px 宽 × 行高；图标 17px + 文字 11px/600 白
槽序（左 → 右）置顶 / 取消置顶 · 完成 · ⋯（已完成行：取消完成 · ⋯）。左滑先露出的必然是最右格（⋯）—— 几何决定；全开时三格同时在位
行宽余量（v4 实测）行左移后可见的是行右端 394 − open 那一段：全开 252px 时可见 138px（时间仍在最右可见，名字/预览只剩尾部约 88px，是尾部不是开头）；拖动途中（如 84px）行跟手位移、头像移出，那只是过渡态不停留
一次只开一行开新行前旧行直接回 0（不做并行动画）
列表一滚即关列表真实滚动量 |ΔscrollTop| > 6px 即关（不按手指 dy 判）
关行不吃点击行开着时点行内其它区域：只关行，本次点击不透传

这些数是「实现可微调、验收须回归」：真机上若 1.5 倍比导致斜滑误判，允许提数据改，改完群里同步并重跑同一组判定。

① 滑动露出的三格P1

最左格置顶 / 取消置顶（按当前态取反）· 蓝 #3370ff
中间格完成 · 中性灰 #646a73
最右格⋯ 更多 · 深灰 #373c43；点开菜单
一滑到底松手过该行上限一半即全开；没有「露一格 / 露两格」的中间态
不放进滑动删除 —— 只走第三格菜单 + 二次确认，避免误触不可撤销操作

「取消完成」是体验补全、不是能力补全：上游 hide 顺带取消置顶、pin / set_section 顺带取消隐藏，所以验收只验「入口可达 + 结果与上游一致」。

一个字段两个词（要你知道）：界面上的「完成 / 已完成」= 上游 is_hidden / chats.hide，字段名与上游文档仍是 hidden —— 语义没变（完成 = 收起、留档、不删），只是我们的叫法改了。 实现上请把「完成」当显示层文案，别顺手把 is_hidden 或白名单方法名改成 is_done / chats.done，那会和上游对不上。
版面的后果（左滑，数值见「行宽余量」）：全开 252px 时露出的是行右端 —— 时间仍在最右可见，名字/预览只剩尾部约 88px（是尾部，不是开头带省略号）；拖动途中头像会移出、名字左边被切，那只是过渡态、松手就不停留。处理方式：行内容不做位移也不淡出、保持原位（iOS 标准行为，重排会让滑动看着抖），滑回即恢复。 不为 P1 收窄槽宽、也不为版面重排：要「名字从头显示 + 时间常驻」就得重排（例如把名字改到不随行位移的浮层），那是另一个设计，不进本期。
v4 消解：方向改成左滑后，手指是向左走，而系统返回手势是左缘向右拖 —— 两者不再抢，左缘排除区与「加 Capacitor 手势排除插件」都不需要了。右侧没有系统手势；真机上若某 ROM 有右缘手势，再量再定。

③ 已完成 tabP1

  • 位置：顶部 tab 变成 会话 / 已完成 / 自动化（原来是 会话 / 自动化）；没有已完成会话时整 tab 不出现，有则带条数角标。
  • 列表里不再有底部「隐藏」组：「会话」tab 回到 置顶 → 各分组 → 未分组。
  • 点「已完成」筛出全部已完成会话，按最新活动倒序（byActivity）；未读数、运行中状态照常显示；不带置顶角标。
  • 点行照常进详情页（完成不等于不可读）。
  • 没有折叠态：tab 是筛选、不是可折叠的组，所以「默认折叠 + 折叠态存本地」这条随本方案作废（原 avatar:lorca:hidden-collapsed 那段代码删掉）。
  • 实现口径：SectionFilter 加一档哨兵值 __hidden（带前缀，免得跟上游生成的分组 id 撞名）。
  • 「已完成」tab 里每行仍是两格：取消完成 · ⋯（这里「置顶」会顺带把会话移出已完成，两个动作互相抵消）。

④ 删除二次确认P1

  • 形态：底部动作面板（复用 .lorca-move 骨架），标题带会话名。
  • 正文说清影响：全部消息与附件、已读标记一并删除；正在运行的任务会被取消。
  • 红色一行写死「不可撤销，也无法从回收站恢复」；主按钮 --danger，取消为安静按钮。

范围与不做什么

P1① 滑动三格 ② 第三格 ⋯ 菜单 ③ Hidden 组 ④ 白名单扩 chats.hide / chats.mute / chats.delete（各带契约测试）⑤ 删除二次确认
P2静音/取消静音 + 行上静音标记；详情页 ⋯ 补完成与静音。静音不是纯 UI：协议 + 归一化要一起动（mute 现在 avatar 一行都没读）
不做会话重命名、会话搜索、长按菜单、分组拖拽、左滑标记已读、行尾常显 ⋯
「列表一滚即关」按 真实滚动量判，不按手指 dy —— 否则已锁定横向的斜滑会因 dy 抖动把行误关。行上需 touch-action: pan-y，WebView 里才既保住原生纵向滚动又收到横向 pointer 事件。

验收口径（可逐条核）

  • AC-1 常态行向左滑一滑到底：一次手势就把三格全露出来，不再出现「露一格 / 露两格」；三格各 84px，自左向右顺序为 置顶 · 完成 · ⋯，三格贴齐行尾（右）一侧、右侧无缝隙。
  • AC-2 向左滑松手只有两态：125px → 回 0、126px → 全开 252px、220px → 全开 252px；拖过 252px 不再多露；任何一次松手都不停在中间值；向右滑不开格。
  • AC-2b 已开态向右滑 ≥ 42px → 关回 0；向右滑不足 42px → 回全开（也不停在中间值）。
  • AC-3 向左：dx=-20,|dy|=8 → 横向、行跟手；dx=-20,|dy|=25 → 纵向、交回滚动；dx=-20,|dy|=16 → 未起判区、行不跟手。
  • AC-4 A 行开着时滑 B 行，A 立即回 0，只有一行是开的。
  • AC-5 行开着时列表纵向滚动 > 6px，行关闭；按住不动、scrollTop 不变时不关。
  • AC-6 行开着时点行内正文，只关行、不进详情页；行关着时点正文正常进详情页。
  • AC-7 常态行尾没有 ⋯（与「现状 · 改前」屏逐行对比）。
  • AC-7b 版面（左滑全开 252px）：可见 138px，时间仍在最右可见，名字/预览只剩尾部；拖动途中行跟手位移、头像移出属正常过渡；名字/预览不淡出（除滑动本身）。
  • AC-8 点第三格 ⋯ 开菜单，三项齐全（移到分组 / 标记为已读 / 删除会话）；未读为 0 时「标记为已读」置灰；点外面关；返回键先关菜单。
  • AC-9 点「完成」：会话离开原分组、从「会话」tab 消失、顶部出现「已完成」tab（带条数）；切到该 tab 能看到它，未读数与运行中状态都在、置顶角标消失。
  • AC-10 「已完成」tab 是筛选不是折叠组：切到它、杀掉 App 重开仍能看到内容（不涉及折叠态）；另一台设备的分组折叠态不受影响。
  • AC-11 取消完成后会话回到原分组；最后一个取消完成时，「已完成」tab 消失。
  • AC-12 删除：确认面板文案含「不可撤销」与附件/已读/运行中任务三项；确认后行从列表消失；若删的是当前打开的会话，回到列表且不自动打开别的会话。
  • AC-13 白名单三条各有一条契约测试；白名单外的方法仍然 fail-closed。
  • AC-15 已完成行的 ⋯ 菜单第一项写作「移到分组（并取消完成）」——上游 set_section 会顺带把会话移出 Hidden；该行只有两格（取消完成 · ⋯）。
