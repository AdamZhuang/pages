头像（已实现 · 对应提交 27c3b5e7）

  • 四档回退：真实图片头像 → accent 渐变底 + Lucide 图标（由 symbol_name 映射）→ accent 渐变底 + 首字 → 认不出一律回退首字。图片字节由 agent 代读（GET /lorca/bots/:id/avatar），手机 WebView 拿不到本机路径。
  • accent 合法值 8 个：blue / teal / green / orange / pink / purple / red，缺省 / 认不出一律回退 indigo（来源：desktop/theme.go 的 accentColor）。
  • SF Symbol → Lucide 映射表重写而非复制（上游 desktop/icons_lucide.go 是 GPL-3.0，且 329 条是 SVG 形状数据，不需要搬）；只覆盖实际用到的几十个 symbol，其余回退首字。
  • 群聊头像取成员头像簇（2×2 错位叠放，最多 4 个），不是拿第一个成员的颜色 —— 之前那是错的。
  • 频道里进来的外部人（author.kind = contact）用首字母灰底，与 bot 的头像区分开。
  • 群聊里同一 bot 的连续气泡只在第一条挂头像，后续气泡缩进对齐 —— 跟 macOS 客户端一致。

思考过程（本次新增）

  • 呈现：压成一行、字号 11.5、--muted-2、无边框无底色，超长横向 marquee 滚动，放得下就不动；右侧「展开」看全文。
  • 事实要先对齐：lorca 给 app 的 payload 里没有思考正文 —— Message::for_app 只处理 Tool / Permission，落库的只有 Text / Tool / Notice / Permission，text_parts 也只取 Text 段。app 面拿到的思考只有一个状态：job.thinking 事件（macOS 读成「Thinking…」）。
  • 所以这一行现在只能显示「思考中 · 最近一条工具/命令」，或者用 message.updated 的流式正文兜底（那是回复正文，不是思考）。要真思考文本，得先向 lorca 提协议需求，不是 avatar 这边能自己解决的。
  • 依赖：job.thinking 转发已加（提交 0578e259）；思考行当前显示「正在干什么」（如「bash Running」），不声称有思考正文。

例程：失败路径也要显出来（验收项，来自调研实读）

  • routines.run 会失败：已在跑 → “… is running right now.”；额度不够 → budgets.admit 拒绝。UI 不能只做乐观置灰，要把这两种错误显出来。
  • routines.update { enabled: true } 不是纯布尔写：set_enabled 先过 workflows::allow_enable，工作流包里的例程可能被拒，启用失败要有文案。
