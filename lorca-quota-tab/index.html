avatar Bot 页「额度」Tab · UI 稿 v1（issue #3）

Tab 顺序按研发核过的现状：会话 / 已完成 / 自动化 / 额度（额度排最后）。 key 由 Adam 自己在页面里填，稿子里没有任何真实凭据，输入框里的圆点全是假的。

P1 · 本期做 原因码口径已与研发锁定 不做：CPA / 告警 / 用量明细 / 自动刷新

Tab 与页面骨架 AC-1

  • 四档：会话 / 已完成 / 自动化 / 额度，额度排最后（图 ① 是改前的三档，只用来对比）。
  • 「已完成」仍只在真有已完成会话时出现（issue #1 定稿），额度永远出现 —— 它是入口，不是有数据才给的列表。
  • 额度页顶部一行：左边「ClinePass」，右边「刷新」+「上次更新 16:20」。进入 Tab 拉一次，之后只靠这个按钮（不做轮询）。

没配 key 时不画两块 AC-2

按研发的倾向定稿：not_configured 时不渲染余额 / 配额两张卡，屏上只有一条状态条 + 「设置 API key」按钮。

理由：两块都必然空，各降级一次就是两行「取不到」，比空态更糊。空态要有明确下一步，不是把「没东西」排两遍。

原因码与人话 AC-4 / AC-6

码层级主文案下一步
not_configured全局还没设置 Cline API key设置 API key
key_invalid全局这个 key 不被接受替换 key（附：到 Cline 账户页重新复制）
network_unreachable全局连不上 Cline，检查网络后再试重试
upstream_no_data块级Cline 返回了空数据，暂时取不到重试
quota_unavailable块级上游没有提供读取订阅配额的接口可在 Cline 官网账户页查看用量
层级不许串：前三条是全局条，后两条只出现在它自己那张卡里。前端只按码取文案，不许自己拼英文、不许把上游原文或 HTTP 状态码写进界面。

两块独立降级 AC-7

  • 块一 Cline 账户余额：有值就显示数值，不加货币符号（上游只给 number，单位不知道就不写）；小字固定一句「Cline 账户余额，不是 ClinePass 订阅配额」。
  • 块二 ClinePass 订阅配额：常态就是 quota_unavailable，不做百分比假进度条。
  • 余额这块挂了不影响配额块那行文案（图 ④：余额空数据，配额照常说明原因）。
  • 没有 resetAt 就不渲染「重置时间」这一行，不留空行占位（本稿所有屏都没有这一行，因为接口当前不给）。
  • key_invalid / network_unreachable 时两块保留骨架、内容位写「—」+ 一句「拿到有效数据后显示」；不重复全局条的原因文案（图 ⑤⑥）。

设置 key AC-3 / AC-5

  • 复用抽屉版面与密文/明文切换，提交改打桌面端新端点（研发方案：PUT /clinepass/key）。
  • 保存成功只回 toast「已设置」；永不回显，重新打开弹层输入框是空的（要改就是重填，不是编辑旧值）。
  • 清除走二次确认，文案「清除后将看不到额度」；清完回到图 ②，落盘文件由后端删除。
  • 保存失败留在弹层里、给一行错误 + 保留输入内容（不吞掉用户刚粘的那串）。
