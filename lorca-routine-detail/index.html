这稿定了什么

数据来源：~/Desktop/code/lorca（GPL-3.0，只读口径、不抄代码）—— crates/cli/src/app.rs 的 routine_out / routine_state、crates/cli/src/model.rs 的 Routine、crates/cli/src/routine_health.rs 的 CheckHealth、mobile/app/chat-info/routine/[id].tsx、macos/Sources/Lorca/Sheets/RoutineViewController.swift。

1. 先纠一个前提：lorca 没有「安卓端」

  • lorca 的移动端是 Expo / React Native（mobile/，expo-router + RN 0.86），一个代码库出 iOS 和 Android，不是原生安卓。所以参考对象是 mobile/app/chat-info/routine/[id].tsx（337 行的 Mac 版是 RoutineViewController.swift）。
  • 别照搬它：lorca 的详情是「表单式」的 —— 上游允许在详情里改名字、排期、时区、错过策略，因为它自己就是例程的属主。avatar 是只读面板，改动一律回会话里让 bot 做（这也是 lorca Mac 版 footer 的原话：ask in chat）。
  • 但结构可以照抄，三段就行：状态头（现在怎么样 + 出问题怎么办）→ 动作 → 调度/任务/检查的只读明细。lorca 两端都是这个顺序，说明它经得住用。

2.1 六态文案表（产品拍板稿）

状态词一律取上游 state，界面不推导。括号里是这一档的判定来源。

state状态词人话（第二行）动作区
on开启「{排期} 由 {bot} 运行，结果发在这个会话里。」运行一次 · 暂停
running正在运行…「{bot} 正在这台机器上跑这一轮，过程发在会话里。」运行一次置灰（正在跑，等它结束）· 暂停可用，副文案说明不影响这一轮
paused已暂停「到点不再运行，历史与配置都留着。启用后从那一刻重新算排期。」启用

failed · 检查线检查失败「检查脚本报错退出了。{bot} 拿到了这个错误，能让它改；它会按退避重试。」运行一次 · 暂停

blocked · 检查越权检查被拦「检查脚本想做一件它没权限做的事。跟 {bot} 说，让它改。」运行一次 · 暂停

failed 三支的状态词都是「检查失败」，只有人话分行。用户要先知道「它现在不工作」，再知道「是哪里坏了」—— 状态词是给眼睛扫的，人话是给脑子读的。（本表 2026-10-15 修正：初稿给三支写了三个状态词，与「状态词不拆」自相矛盾，研发指出后改掉。）

判定口径（研发修正，产品采纳）：不能用「health.model.status 有值」当模型线 —— 实测健康例程的 health.status 是 ready 而不是 null，model.status 也可能有值，「有值」会把健康例程算进检查线。正确写法是先看 state === "failed"（上游 routine_state 已经算好），再在页内分来源：health.model.status === "failed" → 模型线，再看 authentication_failures > 0 分登录被拒、否则 connection_failures > 0 分连不上；两者都是 0 就兜一句通用模型线文案。否则 health.status === "failed" → 检查线。

后四行来自研发的实测发现：health 有两个写入点 —— 检查跑完（routines.rs:742 的 checked()）与运行连不上模型（routines.rs:559 的 record_failure，调用点 turns.rs）。所以 failed 至少有三条来源，「检查脚本报错退出了」不能当通用文案。另外 CheckStatus 是四值（quiet / ready / failed / blocked，routine_health.rs:31），健康例程的 status 是 ready。

2.2 三条要改的地方（研发实测，产品已确认）

发现产品决定工作量
schedule_text 上游下发的是英文（「Every day at 4:30 AM」「Weekdays at 8:30 AM」，来源 schedule.rs:398-455） 要中文化，认到「列表入口 + 详情页」里。理由：排期是这页最常看的一行，夹英文是面板里唯一的中英混排；lorca 手机端自己就写了这个转换（mobile/src/ui/format.ts:84-114），说明上游不打算做本地化。照它的口径重写（不抄代码）：先匹 Every day / Weekdays / Weekends / Every N days|hours|minutes / Every hour at :MM / On the … of every month，认不出的原样显示（Cron … 直接留英文，不编） 0.5d（研发原估，认可）
blocked 态点「运行一次」必 502：上游拒绝文案是「… is paused after three failed sign-ins in a row. Reconnect, then resume it.」（routines.rs:496），translateRoutineError 认不出 桥接层补一条映射：匹 /paused after three failed sign-ins/ → 409 + lorca_routine_signed_out + 中文「还没重新登录，这个例程现在跑不起来；在设置里重新连上供应商再启用」。同时详情页在 blocked 且 paused_reason === "authentication" 时，把「运行一次」直接置灰并给出这句原因 —— 不靠用户点了才知道。UI 稿已补这一屏 含在详情页 4.4d 内
health.model 与 health.status 两条线都会把例程推成 failed，没 check 也会 按来源分三句（见 2.1 表）。原稿「检查脚本报错退出了」只当检查线用。但不分状态词：三支仍统一显示上游 failed 对应词「检查失败」，只有人话分行。判定精确到 health.model.status === "failed"，不能写「有值」（健康例程的 health.status 是 ready，会把健康例程算进检查线 —— 研发实测指出） 含在详情页 4.4d 内

3. 白名单：本期一个新方法都不用加

  • 详情页要的字段上游本来就在 roster 里：routine_out 是在 Routine 的 serde 输出上补了 schedule_text / next_run_at / is_running / state，而 prompt、check、health、missed_run_policy、timezone 本来就在 Routine 里（来源：model.rs:937）。
  • 缺的是桥接层丢字段：services/desktop-agent/src/lorca/client.ts 的 asRoutine() 现在只挑 14 个字段，health / check / missed_run_policy 被丢掉。改动是加字段透传，不是加方法。
  • 动作只有 routines.run 和 routines.update { enabled }，两个都在白名单里。

4. 本期不做，以及为什么

  • 删除例程：需要 routines.delete（不在白名单）。而且「在手机上删掉一个会定时起 turn 的东西」不该是面板里的顺手动作 —— 先只读。
  • 在详情页编辑排期 / 任务 / 检查：需要 routines.update 的其余字段 + 一套表单。lorca 自己都要 routines.describe 校验排期串，avatar 没有这个能力，也不该有。要改就在会话里说。
  • 运行历史（过去 N 次的列表）：上游没有这个数据。CheckHealth 只留最近一次（last_check_at / last_success_at / status / 失败次数 / retry_at），没有 runs 列表，也没有 routines.history 方法。要做就得先提上游需求。
  • 停掉正在跑的这一轮：上游没有 routines.stop，只能走 chats.stop。本稿只在运行态用文案指路，不加按钮。
  • 事件例程（监听 PR）/ 日历例程 / 一次性提醒：字段在（events / calendar / once_at），但三种形态各要一套文案，且 events 还牵扯 GitHub App 安装、webhook key 展示与重置（routines.regenerate_key 不在白名单）。放 P2，本期详情页只做定时例程。
  • 额度 / Limits：lorca 两端都有「额度用尽则暂停」这一档（limitsSummary）。avatar 没有 budgets 数据源，本期状态头里不出现这一档，但状态词表要留位置。

5. 验收标准（研发交付时按这个验）

估工（研发定稿，2026-10-15）：列表入口 0.5d + 详情页 4.4d = 4.9d，报 5 天。产品侧原记的 3.75 是研发上一版算错的数（子项相加实为 4.0），不是「没算中文化」；本次拍板新增三项（列表行中文化 0.1 + blocked 桥接映射 0.1 + failed 三分支 0.25 + 测试增量 0.05）。可砍项（需产品同意）：排期中文化 0.6（面板里唯一的中英混排，已明确不接受）、fixture 测试 0.15、真机/真数据核对 0.25。不含：评审、安卓真机回归（返回键行为只能真机验）。

  • 列表页每行整行可点进详情，右侧不再有「运行 / 暂停」按钮；误触不会起 turn。
  • 详情页六个状态（on / running / paused / waiting_for_runner / failed / blocked）各有对应文案，状态词直接显示上游的 state，界面不自己推导。
  • waiting_for_runner 时「运行一次」不可用，且给出原因。
  • is_running 时「运行一次」不可用、文案是「正在跑」；点「暂停」不会误伤当前这一轮。
  • failed 时能显示上次检查结果与重试时间；没有 check 的例程不显示「检查」段。
  • 无 check 的例程不显示「上次检查 / 上次成功的检查」两行。
  • roster 实时更新到达时，详情页跟着变（例程可能在别的设备上被改）。
  • 停止 / 删除 / 编辑在这页都不可达（要么没有入口，要么明确置灰并说明去哪做）。
  • failed 三支的状态词都显示「检查失败」（不拆），只有第二行按来源分三句；判定用 health.model.status === "failed"，不得用「有值」。
  • 「检查」段与「上次检查 / 上次成功的检查」的显示条件是 check !== null，不是 health !== null（没 check 的例程也会因模型线进 failed）。

6. 已确认与待确认

已确认（2026-10-15，研发定稿采纳）：

  • health.model 与 health.status 两条失败线合并成一个状态词（「检查失败」），只把「怎么修」分行 —— 分开是运维视角，不是用户视角。
  • schedule_text 中文化写成共用函数 scheduleText()，列表行与详情页都调它，按真实 8 个值做 fixture。
  • 白名单不扩（18 个方法内已覆盖）；bootstrap 走 internalMethods。
  • 「等待 Runner」保留英文 Runner，不改成「运行机」（研发核到上游背书：lorca mobile/src/i18n/zh.ts:481 是 "Runner": "Runner" 原样不译、zh.ts:845 是 "Waiting for Runner": "等待 Runner"，与本文状态词一字不差；avatar 自己 LorcaPanel.tsx:144 也已在用「Runner 离线」）。另：「运行机」在 avatar 的 apps/mobile/src、packages/protocol、services/desktop-agent/src 三个目录里零命中 —— 改它等于凭空造一个用户没见过的词。

待确认：

  • 状态词的中文措辞是否定稿（「开启 / 正在运行… / 已暂停 / 等待 Runner / 检查失败 / 等一个登录 / 检查被拦」）？特别「等待 Runner」这个词 —— lorca 手机端英文是 Waiting for Runner，中文里「Runner」是保留英文还是改成「运行机」？我倾向保留，因为 lorca 自己的中文文案也用 Runner，用户已经认识这个词。
